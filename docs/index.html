Forecasting when several futures are possible

Forecasting often begins with incomplete information. We may observe a system's recent motion without knowing all the parameters that govern it. Several futures can then fit the observed history. A planner needs forecasts that capture those alternatives, and it needs them quickly enough to compare many possible actions.

Variational Streaming Flow (VSF) generates future trajectories by advancing a learned dynamical model directly in physical time. We sample a latent code once for each forecast and keep it fixed as the state evolves. Different codes can produce different continuations from the same observations.

We test whether these forecasts stay accurate over 1,000 steps, capture uncertainty when a dynamical parameter is hidden, and help a world-model planner reach its goals.

Read the paper abstract

Probabilistic forecasting is important for predicting complex dynamical systems because intrinsic randomness and incomplete observations can cause the same observed state to evolve into multiple plausible futures. While flow matching is a flexible approach for probabilistic forecasting, it is computationally expensive. Streaming flow (SF) reformulates this approach to model temporal evolution efficiently by learning a continuous velocity field directly in physical time. However, SF learns a deterministic velocity field. Thus, it provides only a single future trajectory for a given fixed initial state and observation history. To overcome this limitation, we introduce Variational Streaming Flow (VSF). Our approach learns a latent distribution that is conditioned on the dynamics of interest. In turn, this enables probabilistic forecasting. Importantly, we retain the computational efficiency of SF by generating in physical time. Across deterministic and stochastic dynamical systems, VSF demonstrates superior predictive accuracy and distributional fidelity. We demonstrate the advantage for both long-horizon rollouts exceeding 1,000 steps, and settings with bifurcating dynamics. Moreover, VSF can be integrated into existing Joint-Embedding Predictive Architecture (JEPA)-based world models as a plug-and-play predictor to improve temporal dynamics and goal-directed success rate in navigation, motion planning, and manipulation.

What this makes possible

A forecast must be useful as a complete path, and affordable to generate repeatedly. These are the two demands behind VSF.

1 · Generating a forecast

Two clocks in generative forecasting

Many diffusion and flow forecasters refine noise into a prediction through an iterative generation process. That process has its own clock: several network evaluations may be needed to generate states at a given physical time. The animations show how this extra computation is organized across a full trajectory, a block of states, or one state at a time.

Watch which future states are being generated and when they become available. The first three methods refine a full trajectory, a block, or a state before making that part of the forecast available. Streaming Flow advances the predicted state directly along the physical timeline.

Observed history Being generated Completed forecast Waiting

All four approaches generate future trajectories. Their computational structure differs. Full-sequence diffusion refines a requested horizon together; block and autoregressive diffusion repeat refinement as the forecast grows. Streaming Flow removes that inner loop. With an Euler update, one evaluation of its velocity field advances the forecast by one step.

2 · Physical-time flow

What is Streaming Flow?

A velocity field tells a state how to move next. Streaming Flow learns this motion from observed trajectories, then follows the learned field from the latest observation. Advancing the dynamics advances the forecast itself.

Build training examples around a path

Start with an observed training trajectory and add small perturbations around it. This creates a tube whose width shrinks with physical time. The tube defines a training construction around one path; uncertainty between possible futures is represented separately by VSF's latent code.

Ys = ξ(s) + σ(s)ε, σ(s) = σ0e−κs

Learn one physical-time field

The target velocity follows the observed motion on the path and points nearby states back toward it. Training fits a neural velocity field to these local targets. The animation illustrates the field we want the model to learn.

LSF = E‖vθ − gξ‖²

Roll forward one step at a time

Start from the latest observation. At step k, the field reads normalized physical time sk and the observed and rolling history h, then advances the state directly.

x̂k+1 = x̂k + Δt vθ(x̂k, sk, h)

4 · Method

Variational Streaming Flow

VSF adds a latent code to the physical-time velocity field. We draw the code before a forecast and keep it fixed throughout the rollout. The predicted state changes at every step, while the code continues to condition how it moves. A new draw can produce a different complete future from the same observations.

The forecast follows the learned latent-conditioned dynamics:

d x̂s / ds = vθ(x̂s, s, h, z)

Training

Sample a transition from an observed training trajectory to obtain a local state and physical velocity (xs, us). An encoder infers codes that explain this motion.

z(1:M) iid∼ qφ(· | us, xs, s, h)

Evaluate the corresponding physical-time velocities.

ûs(1:M) = vθ(xs, s, h, z(1:M))

Optimize generalized energy reconstruction together with KL regularization toward p(z).

Inference

Sample z ∼ p(z) and retain it throughout the forecast.

Advance the predicted state directly in physical time.

x̂k+1 = x̂k + Δs vθ(x̂k, sk, h, z)

Append generated states to the rolling history and refresh h at each segment boundary.

Local supervision, complete forecasts

Local transitions tell the model how a trajectory moves. At inference, we repeatedly apply the learned field to its own predicted states, using the same code at every step. Together, these steps define a distribution over complete future paths:

z ∼ p(z), x̂m+1:T = Rolloutθ(xa:m, z)

The history representation is refreshed from generated states as the rollout proceeds; the code stays fixed across those updates. We assess the resulting path distribution with the complete-trajectory metrics in the stochastic experiments below.

Latent velocity model

At one physical time, let cs = (xs, s, h) collect the state, time, and history. The paper formulates a conditional model of the observed velocity us. Integrating over possible codes gives its conditional velocity distribution:

maximize log pθ(us | cs), where pθ(us | cs) = ∫ pθ(us | cs, z)p(z) dz

Learning a distribution of local motion

At each sampled transition, we want the predicted velocities to capture the observed motion and its uncertainty. The paper studies a generalized energy reconstruction term that scores M latent-conditioned velocity samples together:

Why not use MSE alone?

A variational encoder infers z from the motion observed during training. If that code does not fully separate the possible futures, MSE averages the unresolved velocities toward their conditional mean, v*(c, z) = E[U | C = c, Z = z]. The result can fall between valid motions.

LES(s) = (1/M) Σi ‖ûs(i) − us‖₂α − (1/2M²) Σi,j ‖ûs(i) − ûs(j)‖₂α, 0 < α < 2

The first term rewards accuracy against the observed velocity; the pairwise term accounts for the spread among samples. The full objective adds KL regularization to keep the training-time codes close to the prior used for forecasting:

LVSF = E[LES(s) + βKL KL(qφ(z | us, xs, s, h) ‖ p(z))]

Prior-predictive energy-distance control

Fix c = (xs, s, h). Assume 0 < α < 2, the required α-power expectations are finite, and the aggregate posterior equals the inference prior, q̄φ(· | c) = p. Then

Prediction–truth mismatch: ½Dα(Ũ, U) ≤ EU[Sα(U)]: population training reconstruction loss

Under these assumptions, the population reconstruction term bounds the discrepancy between velocity distributions at this local context. This is a local velocity guarantee. The quality of complete generated trajectories is assessed separately in the forecasting experiments.

What does aggregate posterior matching mean?

We construct a two-branch example to make q̄φ(z | c) = p(z) concrete:

  • Inference prior: p(z) = (0.50, 0.50), so either branch is sampled with equal probability.
  • Training posteriors: the encoder assigns (0.85, 0.15) for U = −1 and (0.15, 0.85) for U = +1, ordered as (P(Z = −1), P(Z = +1)).
  • Aggregate posterior: averaging over the two equally likely targets recovers the inference prior.
q̄φ(z | c) = ½(0.85, 0.15) + ½(0.15, 0.85) = (0.50, 0.50) = p(z).

Objective type. Replacing Gaussian reconstruction with LES makes the final loss a KL-regularized distributional objective.

5 · Results

Dynamical-system forecasting

We first ask whether VSF can track a single correct future over 1,000 steps. We then hide a dynamical parameter and test whether its samples recover the resulting range of possible futures. These settings call for different behavior: concentrated predictions when the continuation is known, and appropriate variation when it is uncertain.

The tables compare performance across the test data. The animations show selected rollouts so we can inspect how errors develop and how the predicted trajectories differ.

5.1

Tracking a single future

In these deterministic benchmarks, each initial condition has one correct continuation. A probabilistic forecaster should place its samples close to that trajectory. Small prediction errors can grow as a rollout advances, so we evaluate the full 1,000-step forecast to see how well each method maintains agreement with the reference motion.

5.2

Forecasting several possible futures

We now hide one dynamical parameter of the Rössler or Lorenz system. The parameter is drawn once for each trajectory and stays fixed during its evolution. Different values can produce closely aligned observed histories followed by different futures. The forecaster must account for this unresolved information.

The target is a distribution of complete future paths. Samples should cover the variation in the reference trajectories while following the system's dynamics. Too little variation misses possible outcomes; variation that carries trajectories away from the system is also an error.

Each generated trajectory is a possible continuation of the observed history. Compare the range and shape of paths across methods; individual samples are not paired with particular reference draws. These galleries show a small selection, while Table 2 evaluates distributions across the test data.

6 · World-model planning

Planning with predicted futures

Forecasts matter when a planner acts on them. To move an object to a target, it must predict what different actions will do before choosing one. Prediction errors can make an ineffective action look promising, and the cost of forecasting matters when the planner evaluates many candidates.

We test VSF inside LeWM, a world model built on a joint-embedding predictive architecture (JEPA). An encoder represents the current and goal images as compact visual features. The predictor forecasts how those features will change under a candidate action sequence. The Cross-Entropy Method (CEM) planner searches for a sequence whose predicted endpoint is close to the goal. We compare the original autoregressive (AR) predictor with SF and VSF while keeping the encoder, planner, and planning budget fixed.

7 · Next steps

What comes next

Contact can change motion abruptly. VSF learns local motion from adjacent observations, which can be difficult to resolve near an impact or when observations are noisy. A model that combines continuous evolution with explicit jumps could extend this approach to such events. Higher-order or adaptive integration could reduce integration error at the cost of additional field evaluations.

A persistent latent code is useful when uncertainty affects an entire continuation, as in the hidden-parameter experiments. Other settings also contain disturbances that arrive during a forecast. Combining a persistent code with new sources of randomness, and updating uncertainty as observations arrive, could help model both kinds of variation.

Planning offers a further direction. Evaluating several predicted futures for each candidate action sequence would let a planner assess how reliably that action reaches the goal. A useful next experiment would test whether this improves decisions when outcomes vary, especially when some failures are much more costly than others.
