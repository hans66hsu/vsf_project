Variational Streaming Flow:

Probabilistic Forecasting in Physical Time

Time series describe how systems change, whether we are studying the weather or controlling a robot arm. These are often multivariate problems: temperature, pressure, and wind evolve together, as do a robot's joint positions and velocities. Forecasts need to capture those relationships. They also need to account for what we do not know. A robot may have to move an object before it knows the object's mass or friction. A single predicted motion can hide that uncertainty. A probabilistic forecast describes the range of motions the robot might encounter.

Generating these possible futures can be expensive. Diffusion models start from noise and refine it through repeated network evaluations, either for a whole trajectory or for successive states or blocks. A planner that compares many actions must repeat that work many times. Streaming Flow (SF) avoids a separate denoising loop: it learns the state's rate of change and integrates forward in physical time. With Euler integration, one network evaluation advances the forecast by one step. Standard SF, however, produces only one future from a fixed starting state and history. It needs another source of variation to describe alternative futures.

We introduce Variational Streaming Flow (VSF), which gives the dynamics model an extra input: a randomly sampled latent code. The code stays fixed as the model predicts successive states. Drawing a different code can produce a different trajectory from the same observations. During training, an encoder uses observed transitions to infer codes that explain the motion. At prediction time, we draw the code from a standard normal distribution. The model then updates all state variables together, with one field evaluation per Euler step for each trajectory. We test VSF on 1,000-step forecasts of physical systems and in a visual world model that uses predicted motion to plan actions.

From forecasting to planning

Long forecasts give prediction errors time to grow. Once a model starts using its own predictions as inputs, an early mistake can affect every later step. This is known as error accumulation in autoregressive prediction. We test VSF over 1,000 steps, measuring whether it follows the system's motion and captures the variation caused by a hidden parameter. We then use its forecasts to choose actions in a visual world model: the planner predicts what each candidate plan will do before selecting one to execute. A misleading forecast can make a bad plan look promising. The chart below shows planning success on four tasks, with the visual encoder, planner, and planning budget held fixed.

1 · Generating a forecast

Two clocks in diffusion forecasting

Diffusion starts with a noisy guess of the future and refines it through repeated network evaluations. This introduces two clocks: the physical time covered by the forecast, and the progress of denoising. The model can spend many evaluations refining a prediction without advancing physical time. Full-sequence diffusion refines a requested horizon all at once. Block diffusion generates a few future states together, while one-step autoregressive diffusion repeats denoising for every next state. Streaming Flow advances the predicted system directly in physical time. Each integration step produces the next state. The animations below show when predictions become available under each approach.

These choices affect how a forecast can be used. A joint model needs a forecast horizon up front, while block and one-step models can extend the forecast using their earlier predictions. SF can also continue its rollout, with one field evaluation per Euler step. This count explains where it saves computation, but the cost of a network evaluation differs across architectures. Refining a whole sequence is a different amount of work from updating one state. We therefore report measured runtimes alongside forecasting accuracy below.

2 · Physical-time flow

What is Streaming Flow?

To forecast directly in physical time, SF learns how fast each variable in a system's state changes. For our double pendulum, the state contains the positions and velocities of both masses; in the robot experiments, it contains visual features. The model predicts their rates of change together, and integrating those rates produces a trajectory. Even a small prediction error can put the forecast at a state that never appeared in the training data. SF defines training targets around each observed path so the model can learn what to do there. These targets combine motion along the path with a correction toward it.

Build training examples around a path

Start with an observed trajectory, ξ(s), and add Gaussian noise around it. This gives the model examples of states slightly away from the path. The noise decreases over physical time, so these examples form a narrowing tube. Each tube belongs to one observed trajectory. Its width controls the training perturbations; variation between possible future trajectories is a separate question.

Ys = ξ(s) + σ(s)ε, σ(s) = σ0e−κs

Learn one physical-time field

At each training state, the target combines the observed velocity with a correction, gξ(x, s) = ξ̇(s) − κ(x − ξ(s)). The correction is zero on the path. Away from it, the correction points back toward the path while the reference velocity carries the state forward. Standard SF learns these targets by squared-error regression.

LSF = E‖vθ − gξ‖²

Roll forward one step at a time

Start from the latest observation and ask the learned field how the state should change. An Euler update uses that prediction to advance one step. Repeat from the new state, adding generated states to the rolling history. These updates are autoregressive: each predicted state helps determine the next. The field receives the current state, normalized physical time sk, and a history representation h. With the same starting state and history, standard non-latent SF produces the same trajectory.

x̂k+1 = x̂k + Δt vθ(x̂k, sk, h)

3 · Bifurcation example

How a latent code separates futures

We use a single-variable example to see why a separate code helps. Two futures follow the same path until a branch point and then move in opposite directions. This splitting into two possible futures is the bifurcation in our example. The shared past gives no clue about which branch will follow. Standard SF can send forecasts toward either branch by starting slightly to either side of the split state. Making those perturbations smaller improves the fit at the split, but asks the field to send nearly identical states in different directions. In this example, that makes the field increasingly sensitive to small state errors. A latent code can choose the branch while both forecasts begin at exactly the same physical state.

Bifurcation example

Start with two equally likely futures that are mirror images of one another. Both remain at the same state until a chosen time, then separate symmetrically. This lets us compare two things: how closely each model matches the state at the split, and how much it amplifies small state errors afterward.

4 · Method

Variational Streaming Flow

We train an encoder and a velocity network together. The encoder sees an observed transition and proposes latent codes that help the velocity network explain its motion. The network learns how each code changes its prediction, given the current state, time, and history. The posterior describes which codes are likely given the observed motion. Computing it exactly is difficult, so the encoder predicts the mean and variance of a Gaussian approximation. This is the variational inference step that motivates our training objective. When forecasting, the future motion is unknown, so we draw a code from a fixed standard-normal prior, p(z) = N(0, I), and keep it throughout the rollout. A Kullback–Leibler (KL) penalty encourages the encoder's distributions to stay close to this prior. This helps match the codes used during training to those drawn when forecasting. The paper also relates this variational approach to earlier SF extensions with auxiliary latents.

The forecast follows the learned latent-conditioned dynamics:

d x̂s / ds = vθ(x̂s, s, h, z)

Training

Take a transition from a training trajectory and compute its local state and velocity (xs, us). The encoder proposes codes that could explain this movement.

z(1:M) iid∼ qφ(· | us, xs, s, h)

For each code, predict the velocity at this state and time.

ûs(1:M) = vθ(xs, s, h, z(1:M))

Train both networks with the energy reconstruction loss below and a KL penalty toward p(z).

Inference

Sample z ∼ p(z) and retain it throughout the forecast.

Advance the predicted state directly in physical time.

x̂k+1 = x̂k + Δs vθ(x̂k, sk, h, z)

Append generated states to the rolling history and refresh h at each segment boundary.

How local predictions become complete trajectories

Each training example tells the network how the state moves over a short interval. To generate a forecast, we start from the last observation, predict its rate of change, and update the state. We then evaluate the network at this new state and repeat. Generated states enter the rolling history, and the same latent code stays in use as that history is refreshed. This gives one complete trajectory from the observed history and code. Drawing a new code and rerunning the forecast can give another future:

z ∼ p(z), x̂m+1:T = Rolloutθ(xa:m, z)

We evaluate this distribution using full trajectories in the stochastic experiments. In the ablation in Figure 11, keeping the code fixed gives more accurate long forecasts than resampling it at every step. The theorem below addresses the local velocity distributions used to build those trajectories.

Latent velocity model

Let cs = (xs, s, h) collect the state, time, and history, and let us be the observed velocity. For the training derivation, we place a Gaussian distribution around the velocity predicted for each code at this context. Averaging these distributions over the prior gives the conditional velocity likelihood:

maximize log pθ(us | cs), where pθ(us | cs) = ∫ pθ(us | cs, z)p(z) dz

The encoder makes this model practical to train by proposing codes from the motion observed in the training data. The paper first derives an evidence lower bound (ELBO): with a Gaussian reconstruction model, this gives squared error plus a KL penalty. We then replace the squared-error reconstruction with the energy term below. The final loss is a KL-regularized distributional objective. At inference, the network returns a single velocity for the sampled code and current context.

Learning a distribution of local motion

When a system can move in several ways, we want the samples to reproduce those motions in the right proportions. We therefore train the predicted velocities together as a distribution. For each observed transition, we draw M codes from the encoder's distribution and predict a velocity for each. The generalized energy reconstruction loss scores these velocities using both their distance to the observed motion and their differences from one another.

Why not use MSE alone?

Suppose velocities −1 and +1 remain equally likely at the same context and code. Squared error favors their average, 0. An informative code can separate the two directions. Any uncertainty left after conditioning is still averaged: v*(c, z) = E[U | C = c, Z = z]. This motivates training the predicted velocities as a distribution.

LES(s) = (1/M) Σi ‖ûs(i) − us‖₂α − (1/2M²) Σi,j ‖ûs(i) − ûs(j)‖₂α, 0 < α < 2

In the paper's formulation above, the first term pulls predictions toward the observed velocity. The subtracted term rewards differences among predictions. The two terms work together: spreading samples too far apart also increases their distance from the observation. The exponent sets how strongly large distances count. We add the KL penalty to encourage codes inferred during training to remain close in distribution to the prior used for forecasting:

LVSF = E[LES(s) + βKL KL(qφ(z | us, xs, s, h) ‖ p(z))]

What does aggregate posterior matching mean?

We construct a two-branch example to make q̄φ(z | c) = p(z) concrete:

  • Inference prior: p(z) = (0.50, 0.50), so either branch is sampled with equal probability.
  • Training posteriors: the encoder assigns (0.85, 0.15) for U = −1 and (0.15, 0.85) for U = +1, ordered as (P(Z = −1), P(Z = +1)).
  • Aggregate posterior: averaging over the two equally likely targets recovers the inference prior.
q̄φ(z | c) = ½(0.85, 0.15) + ½(0.15, 0.85) = (0.50, 0.50) = p(z).

5 · Results

Forecasting dynamical systems

A model can predict the next step well and still lose track of the motion over a longer forecast. Once it starts using its own predictions, an early mistake changes the states it encounters later. We test this over 1,000 steps on the double pendulum, Rössler, and Lorenz systems. All three require multivariate prediction: the pendulum has eight state variables, and Rössler and Lorenz each have three. We first test deterministic systems with the full state observed, so there is one correct future to follow. We then hide a parameter in the Rössler and Lorenz systems and test whether the models predict the resulting range of futures.

We compare VSF with diffusion and rectified-flow forecasters, DeepAR, standard SF, and the pretrained time-series model Chronos-2. SF and VSF use the same U-Net backbone. We also test SF with noise added to its starting state, labeled SF (perturb.), to see how much this simple source of variation helps. Chronos-2 is frozen; its calibrated variant corrects the predicted quantiles after forecasting. The tables cover the test data, and the animations show selected forecasts in more detail.

5.1

Tracking a single future

We begin with deterministic systems whose full state is observed. Their future is fixed by the initial condition. Chaos makes that future sensitive to small errors, but the simulator does not draw a new outcome each time it runs. We therefore want a probabilistic model's samples to stay close to the same reference path. We score the samples with the continuous ranked probability score (CRPS), separately at each time and state coordinate. Root mean square error (RMSE) and mean absolute error (MAE) measure errors in their mean. We report both because averaging can hide errors: several poor paths can have a better-looking mean.

VSF improves on SF even when there is only one future to predict. Since both models advance directly in physical time, this comparison tests the benefit of the variational formulation within the same forecasting approach. Adding noise to SF's starting state helps on some metrics, but leaves a gap to VSF. Chronos-2 has a different setup: it is frozen and receives only 10 context steps, while the other models are trained on these systems.

5.2

Forecasting when a parameter is hidden

For the next experiment, we hide one parameter of the Rössler or Lorenz equations from the forecaster. We draw a value for each simulated trajectory and keep it fixed until the end. Once that value is set, the trajectory follows deterministic equations. Starting from the same initial state, these trajectories look almost identical over the short observed history but later separate. The model must now predict a range of futures. Because we know how the data were generated, we can compare that range with many futures from the simulator.

The samples should cover the same range of motion as the simulator's futures. We first compare the center and spread of the two ensembles at each forecast time, using conditional mean error (CME) and conditional standard-deviation error (CSE). Standard SF produces the same path each time from a fixed input. Its zero spread gives a CSE of one in this experiment.

Two ensembles can have similar means and spreads at each time yet connect those states into different paths. To check the paths themselves, we also report Wasserstein distance (W1) and energy distance (ED). For these scores, we stack every state in a rollout into one vector, in time order, and compare the resulting distributions. The scores therefore assess the full trajectories generated by the model, including how their states depend on one another over time.

The galleries show what these scores are measuring. Compare the spread and shape of each model's paths with the simulator's ensemble. Look for samples that all repeat one motion, or that separate by drifting away from the system. A model sample is a possible future, so it need not match the neighboring simulator sample point for point. These are selected examples; Table 2 summarizes the test data.

6 · World-model planning

Planning with predicted futures

A robot uses a forecast to choose what to do next. Before moving, a planner can try many action sequences in the model and select one that appears to reach the goal. If the predicted motion is wrong, a promising plan may fail when executed. Planning therefore tests whether the forecasts lead to useful decisions. It also makes speed matter: the model may simulate many candidate plans before the robot takes a step. We test VSF in this setting with the visual representation, planner, and planning budget held fixed.

We use LeWM, a visual world model whose pretrained encoder turns each image into a 192-dimensional feature vector. We encode the current scene and the goal in the same way. The predictor forecasts how the current scene's features change under a proposed action sequence. The planner compares the predicted endpoint with the goal's feature vector. To find a plan, it uses the Cross-Entropy Method (CEM): sample action sequences, keep the best candidates, and use them to improve the next round of samples.

With the encoder frozen, we compare LeWM's autoregressive predictor with SF and VSF predictors trained on offline observation–action trajectories. The CEM planner, tasks, and planning budget stay the same. In VSF, the visual feature vector changes at every step, while the sampled code stays fixed throughout the imagined trajectory. Each transition uses one velocity-field evaluation. We measure both whether the chosen actions reach the goal and how closely the predicted feature trajectory matches the observations collected along those actions.

Values are mean ± population standard deviation over three seeds, with 50 goals per seed. Success is the percentage of goals reached within a 50-step execution budget. RMSE measures error in the predicted visual state representations along the action sequence selected by CEM. Higher success and lower RMSE are better.

The planner succeeds only if its chosen actions actually reach the goal. This is a different test from prediction RMSE: on Cube, SF has slightly lower RMSE, while VSF reaches more goals. The predictors also lead the planner to choose different action sequences, so their RMSE values need not describe the same physical trajectories. 7 · Next steps

What comes next

Our hidden-parameter experiments study uncertainty that lasts for a whole trajectory. Many systems also face new disturbances as they evolve. One extension would keep the current code for persistent uncertainty and add new random inputs during the rollout. New observations could then update the forecast as the robot or system reveals more about its dynamics.

Impacts and contact changes raise a different problem: motion can change abruptly between observations. A model that combines continuous evolution with explicit jumps could handle these events more directly. For rapidly changing but continuous motion, adaptive or higher-order solvers could reduce integration error. They require extra field evaluations, so the comparison should measure how much accuracy they buy for a given computation budget.

We also want to test how a planner should use the range of futures VSF predicts. Generating several futures for each candidate plan would let it estimate both expected performance and the chance of failure. This could matter when occasional failures are costly, even if average prediction error is small. The next experiment would compare that planner with the current goal-matching procedure under the same computation budget.
